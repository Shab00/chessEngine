# 🕹️ C Chess Engine to WASM for GitHub Pages

---

## Step 1: Set Up Emscripten Locally (1–2 hours)

**Goal:** Be able to compile `engine.c` (your code) to WebAssembly using Emscripten.

1. **Install Emscripten SDK**
   - [Emscripten Getting Started](https://emscripten.org/docs/getting_started/downloads.html)
   - On Linux/macOS:
     ```sh
     git clone https://github.com/emscripten-core/emsdk.git
     cd emsdk
     ./emsdk install latest
     ./emsdk activate latest
     source ./emsdk_env.sh
     ```
   - On Windows: run the included .bat files and follow the [Emscripten Windows guide](https://emscripten.org/docs/getting_started/downloads.html#download-and-install).

2. **Test Installation**
   - Try `emcc --version` — should output emscripten version #.

---

## Step 2: Build Your Engine as a WASM Module (1–2 days)

**Goal:** Compile your chess engine as a `.wasm` and JS glue code using Emscripten.

1. **Clean your code:**
   - Remove/disable all non-ANSI dependencies (`#include <unistd.h>`, POSIX, etc.)
   - Ensure all user interaction is through functions, not direct I/O. (Web UI will drive the engine.)

2. **Compile Your Engine:**
   - Basic command:
     ```sh
     emcc engine.c -o engine.js -s WASM=1 -s "EXPORTED_FUNCTIONS=['_uci_loop', ...]" -s "EXPORTED_RUNTIME_METHODS=['ccall', 'cwrap']"
     ```
   - **Replace `engine.c` with your C files, and list all functions you want to call from JS.**
   - Example: If you want to call `void uci_loop(void)` from JS, include `'_uci_loop',` in "EXPORTED_FUNCTIONS".
   - To create a "worker" engine, you might need to adapt your engine to use `step()` or `make_move()`, returning a bestmove for each call.

3. **Test:**
   - You should get `engine.js` and `engine.wasm` in your build folder.

---

## Step 3: Prepare a Web GUI with JS Chessboard (2–3 days)

**Goal:** Add a chessboard using a JS library and wire it to your engine.

1. **Pick a JS chessboard:**
   - [cm-chessboard](https://github.com/shaack/cm-chessboard)  
   - [chessboard.js](https://github.com/jhlywa/chessboardjs)  
   - [Bankai chess](https://github.com/bankai/chess)

2. **Set up a basic `index.html` with the board displayed.**
   - Start from a [cm-chessboard Example](https://shaack.com/projekte/cm-chessboard/examples/01-basic-use.html).

3. **Use JavaScript to load your WASM engine:**
   - In `index.html` (or a `.js` file), load `engine.js` (generated by emcc).
   - Use Emscripten's `ccall` or `cwrap` to call into your engine from JS.

4. **Connect moves:**
   - When user moves on the board, call the WASM engine’s function to update the position and ask for a bestmove.
   - Move the piece back on the board once the engine responds.

---

## Step 4: GitHub Pages Deployment (1–2 hours)

**Goal:** Deploy everything as static files.

1. **Place `index.html`, `engine.js`, `engine.wasm`, and all assets in `/docs` or a `gh-pages` branch within your repo.**
   - GitHub Pages serves `/docs` or `/gh-pages` as static files.

2. **Push to GitHub.**
   - Enable GitHub Pages in your repo settings pointing to `/docs` or the right branch.

3. **Test public access:**  
   Go to `https://yourusername.github.io/yourrepo/` and ensure everything loads and runs!

- **Debug locally:**  
  You can run `python -m http.server` in the folder to preview in browser (since WASM requires a web server).
